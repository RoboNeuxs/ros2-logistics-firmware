# ESP32 控制 STM32 串口命令

适用：本仓库 STM32F103C8T6 四路编码电机固件 **V4.3**（版本字段 `0x0403`），协议 V4，参数格式 4。本文以当前源码为准；ESP32 负责发送目标和心跳，STM32 负责四路 PWM、编码器反馈、速度闭环与停车保护。

## 1. 接线与串口设置

| ESP32-S3 | STM32F103C8T6 | 方向 |
|---|---|---|
| GPIO1 / `BOARD_STM32_TX_GPIO` | PA3 / USART2_RX | ESP32 → STM32 |
| GPIO2 / `BOARD_STM32_RX_GPIO` | PA2 / USART2_TX | STM32 → ESP32 |
| GND | GND | 共地 |

双方设置：**115200 波特率、8 数据位、无校验、1 停止位、无流控，3.3V TTL**。TX 接对方 RX。

ESP32 引脚已对照现有 ESP32 工程的 `config/board_pins.h`；该文件不在本固件仓库内，接入 ESP32 工程时继续使用其中的宏。STM32 引脚以 [board_config.h](../STM32/Board/board_config.h) 为准。

Arduino-ESP32 初始化片段如下；放入已有 ESP32 程序，在 `setup()` 中调用 `initStm32Uart()`，并先通过该工程实际的头文件包含路径引入上述引脚宏：

```cpp
#include <Arduino.h>

HardwareSerial stm32Uart(1);  // UART1，用于 STM32；调试输出使用其他串口

void initStm32Uart() {
    // begin 的引脚参数顺序是 RX、TX。
    stm32Uart.begin(115200, SERIAL_8N1,
                   static_cast<int8_t>(BOARD_STM32_RX_GPIO),
                   static_cast<int8_t>(BOARD_STM32_TX_GPIO));
}
```

这部分是通信代码片段，不是完整的 ESP32 运动控制程序。Arduino 串口 API 的参数顺序和 `write(buffer, size)` 用法见 [Espressif 官方说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/serial.html)。

## 2. 先检查通信：PING

发送 ASCII `PING`，或原始字节 `50 49 4E 47`，预期回复 `PONG\r\n`，即 `50 4F 4E 47 0D 0A`。大小写均可，不需要额外换行。

PING 不启动电机、不清故障，也不续期运动心跳。它只能证明文本往返通信；要确认 V4 版本和电机状态，继续发送 `0x14` 查询命令。

## 3. 二进制命令帧：固定 14 字节

除了 PING，控制命令都发送原始二进制数据。表中的 `AA 55 ...` 是字节的十六进制写法；ESP32 应使用 `write(frame, 14)`，不向 STM32 发送这串可见字符，也不在帧后追加回车换行。

| 字节位置（从 0 开始） | 字段 | 说明 |
|---|---|---|
| 0～1 | 帧头 | 固定 `AA 55` |
| 2 | cmd | 功能码，见下一节 |
| 3 | seq | 请求序号 `0x00～0xFF`；每次请求递增，溢出回到 0，应答原样返回 |
| 4～5 | v0 | 第一个 16 位值，低字节在前 |
| 6～7 | v1 | 第二个 16 位值，低字节在前 |
| 8～9 | v2 | 第三个 16 位值，低字节在前 |
| 10～11 | v3 | 第四个 16 位值，低字节在前 |
| 12 | flags | 电机选择器或四台模式组合，随命令变化 |
| 13 | CRC | CRC-8/SMBUS，只计算字节 2～12，共 11 字节 |

运动目标按有符号 `int16` 解释；参数写入的 v1 按 `uint16` 位模式解释。保留字段填 0。正数 `200` 编码为 `C8 00`，负数 `-200` 编码为 `38 FF`；参数值 `60000` 编码为 `60 EA`。

CRC 参数：多项式 `0x07`、初值 `0x00`、不反射、最终不异或。修改功能码、序号、值或 flags 后都必须重新计算 CRC。

## 4. 全部命令与控制模式

下表功能码使用十六进制，模式、目标和参数 ID 默认使用十进制。

| 功能码 | 功能 | v0、v1、v2、v3 | flags / 条件 |
|---|---|---|---|
| `0x13` | 立即停止全部 | `0, 0, 0, 0` | 0；不自动清故障 |
| `0x14` | 查询状态 | `0, 0, 0, 0` | 0；不续期心跳 |
| `0x15` | 清零编码器累计计数 | `0, 0, 0, 0` | 0=全部，1～4=单台；所选电机模式和实际 PWM 均须停止 |
| `0x16` | 单台或全部使用相同模式、相同目标 | `模式, 目标, 0, 0` | 0=全部，1～4=M1～M4 |
| `0x17` | 四台分别设置模式、目标 | `M1目标, M2目标, M3目标, M4目标` | 每两位表示一台电机模式 |
| `0x18` | 心跳 | `0, 0, 0, 0` | 0；续期已接受的全部运动目标，故障时拒绝 |
| `0x19` | 清除故障 | `0, 0, 0, 0` | 0；必须全部停止；不恢复旧运动目标 |
| `0x20` | 读取参数 | `参数ID, 0, 0, 0` | 电机参数必须选 1～4；全局参数用 0 |
| `0x21` | 写入 RAM 参数 | `参数ID, uint16值, 0, 0` | 电机参数 1～4=单台、0=四台；全局用 0；必须全部停止 |
| `0x23` | 恢复默认 RAM 参数 | `0, 0, 0, 0` | 0；必须全部停止 |

`0x16` / `0x17` 使用以下模式：

| 模式 | 含义 | 目标 |
|---:|---|---|
| 0 | 立即停止 | 必须为 0 |
| 1 | PWM | 有符号千分比，协议最大 ±1000；例如 ±200 为两个方向的 20% PWM 请求 |
| 2 | 速度闭环 | 有符号 `count/s`，协议最大 ±10000；不是 RPM |
| 3 | 减速停止 | 必须为 0；按减速参数逐渐降至停止 |

实际目标还受每台 `max_pwm` / `max_speed` 参数限制，越界会被拒绝。四台按 M1～M4 对应板上 A～D；哪台对应左前、右前等车轮位置，以及正号是否对应车辆前进，需要按接线和安装方向确认。

`0x17` 的模式组合方式：

```text
flags = M1模式 | (M2模式 << 2) | (M3模式 << 4) | (M4模式 << 6)
```

四台 PWM 为 `0x55`，四台速度为 `0xAA`，四台减速停止为 `0xFF`；PWM/速度/停止/PWM 为 `0x49`。这里的 flags 不是电机选择位图，不能套用到 `0x16`。

`0x16` 立即停止所选电机以及 `0x13` 会立即清零对应 PWM；`0x17` 四台新目标通过校验后在后续控制周期一起应用，控制周期为 50 ms。收到成功应答表示已接受请求，实际输出还要读取状态帧中的 PWM 字段。

## 5. 可直接检查的 HEX 命令示例

以下每行都是完整的 14 字节请求，包含对应序号和已计算的 CRC。序号一栏为十六进制，仅用于示例；它们不是一套必须按顺序执行的启动脚本。运动例子需在车轮悬空、接线与反馈方向已确认后使用。

| seq | 用途 | v0, v1, v2, v3（十进制） | flags | 完整发送帧（HEX） |
|---|---|---|---|---|
| `01` | 查询状态 | `0, 0, 0, 0` | `00` | `AA 55 14 01 00 00 00 00 00 00 00 00 00 E3` |
| `02` | 立即停止全部 | `0, 0, 0, 0` | `00` | `AA 55 13 02 00 00 00 00 00 00 00 00 00 06` |
| `03` | M1 PWM +200 | `1, 200, 0, 0` | `01` | `AA 55 16 03 01 00 C8 00 00 00 00 00 01 56` |
| `04` | M1 PWM -200 | `1, -200, 0, 0` | `01` | `AA 55 16 04 01 00 38 FF 00 00 00 00 01 5B` |
| `05` | M1 立即停止 | `0, 0, 0, 0` | `01` | `AA 55 16 05 00 00 00 00 00 00 00 00 01 7D` |
| `06` | 全部减速停止 | `3, 0, 0, 0` | `00` | `AA 55 16 06 03 00 00 00 00 00 00 00 00 49` |
| `07` | M1 速度 +500 count/s | `2, 500, 0, 0` | `01` | `AA 55 16 07 02 00 F4 01 00 00 00 00 01 BE` |
| `08` | 四台均 PWM +200 | `200, 200, 200, 200` | `55` | `AA 55 17 08 C8 00 C8 00 C8 00 C8 00 55 1F` |
| `09` | 四台混合 PWM/速度/停/PWM | `200, 500, 0, -200` | `49` | `AA 55 17 09 C8 00 F4 01 00 00 38 FF 49 1A` |
| `0A` | 心跳 | `0, 0, 0, 0` | `00` | `AA 55 18 0A 00 00 00 00 00 00 00 00 00 96` |
| `0B` | 清除故障 | `0, 0, 0, 0` | `00` | `AA 55 19 0B 00 00 00 00 00 00 00 00 00 E1` |
| `0C` | 全部编码器计数清零 | `0, 0, 0, 0` | `00` | `AA 55 15 0C 00 00 00 00 00 00 00 00 00 7A` |
| `0D` | 读取 M1 CPR | `3, 0, 0, 0` | `01` | `AA 55 20 0D 03 00 00 00 00 00 00 00 01 E3` |
| `0E` | 设置 M1 CPR=1560（示例） | `3, 1560, 0, 0` | `01` | `AA 55 21 0E 03 00 18 06 00 00 00 00 01 8B` |
| `0F` | 设置 M1 CPR=60000（编码示例） | `3, 60000, 0, 0` | `01` | `AA 55 21 0F 03 00 60 EA 00 00 00 00 01 74` |
| `10` | 设置全局失联超时=1000 ms | `128, 1000, 0, 0` | `00` | `AA 55 21 10 80 00 E8 03 00 00 00 00 00 AF` |
| `11` | 恢复默认参数 | `0, 0, 0, 0` | `00` | `AA 55 23 11 00 00 00 00 00 00 00 00 00 32` |

CPR 示例不是实际电机标定值。固件默认 CPR=1 是占位值；确认输出轴每圈 A 相下降沿数量后再填写。参数全部保存在 RAM，掉电或复位后恢复默认；当前没有 Flash 保存命令。

## 6. ESP32 组帧与 CRC 代码

下面的 C++ 函数只组装数据，不访问串口。使用 `uint16_t` 保存线上位模式，既能编码负运动目标，也能保留 60000 这样的参数值。

```cpp
#include <stdint.h>
#include <stddef.h>

uint8_t stm32Crc8(const uint8_t* data, size_t length) {
    uint8_t crc = 0;
    for (size_t i = 0; i < length; ++i) {
        crc ^= data[i];
        for (uint8_t bit = 0; bit < 8; ++bit) {
            crc = static_cast<uint8_t>(
                (crc & 0x80) ? ((crc << 1) ^ 0x07) : (crc << 1));
        }
    }
    return crc;
}

void makeStm32Command(uint8_t frame[14], uint8_t cmd, uint8_t seq,
                      uint16_t v0, uint16_t v1, uint16_t v2, uint16_t v3,
                      uint8_t flags) {
    const uint16_t values[4] = {v0, v1, v2, v3};
    frame[0] = 0xAA;
    frame[1] = 0x55;
    frame[2] = cmd;
    frame[3] = seq;
    for (uint8_t i = 0; i < 4; ++i) {
        frame[4 + 2 * i] = static_cast<uint8_t>(values[i]);
        frame[5 + 2 * i] = static_cast<uint8_t>(values[i] >> 8);
    }
    frame[12] = flags;
    frame[13] = stm32Crc8(frame + 2, 11);
}
```

例如，在串口初始化后发送查询：

```cpp
uint8_t frame[14];
makeStm32Command(frame, 0x14, 0x01, 0, 0, 0, 0, 0);
size_t written = stm32Uart.write(frame, sizeof(frame));
// written 必须为 14；之后等待 seq=0x01 的有效 64 字节应答。
```

M1 反向 PWM 示例的组帧调用为 `makeStm32Command(frame, 0x16, 0x04, 1, static_cast<uint16_t>(-200), 0, 0, 1)`。发送前自行检查目标范围、故障和运行条件；组帧函数不代替这些检查。

## 7. 接收应答：固定 64 字节

每条 CRC 正确且已解析的二进制请求返回一帧状态，包含命令成功或拒绝的结果。CRC 错误的请求不应答。当前固件不主动定时上报，ESP32 需要查询或读取其他命令的应答。

| 字节位置 | 含义 |
|---|---|
| 0～1 | `AA 55` |
| 2 | `0x93`，请求应答 |
| 3 | 对应请求序号 seq |
| 4 | 错误码：0=成功；1=未知命令/保留字段错误；2=范围/选择器/部分字段错误；3=当前状态不允许 |
| 5 | 全局故障位，见下一节 |
| 6 | 故障电机位图，bit0～3 对应 M1～M4，表示堵转/无反馈或输入捕获过捕获所涉电机 |
| 7 | 高 4 位为参数格式，当前 4；bit0=0 表示方向由 A/B 反馈得到 |
| 8～9 | 最近有效运动命令/心跳的年龄，uint16 ms，饱和至 65535 |
| 10～20 / 21～31 / 32～42 / 43～53 | M1 / M2 / M3 / M4 状态块，每块 11 字节 |
| 54～55 | 参数读写值，uint16；只在参数应答中解释 |
| 56～57 | 参数 ID、作用域；只在参数应答中解释 |
| 58～59 | 固件版本，小端 `03 04` 表示 `0x0403` |
| 60～61 | 能力位图，正常 V4.3 为 `0x073F` |
| 62 | 参数状态：0=默认，2=RAM 已修改 |
| 63 | CRC，只计算字节 2～62，共 61 字节 |

每台状态块从 `base = 10 + 11 × (电机编号 - 1)` 开始：

| 块内偏移 | 类型 | 内容 |
|---|---|---|
| +0 | uint8 | 模式 |
| +1～2 | int16 | 目标 |
| +3～4 | int16 | 已施加的有符号 PWM，千分比 |
| +5～6 | int16 | 编码器速度，count/s |
| +7～10 | int32 | 累计编码器计数，按 32 位回绕 |

接收按字节流处理：寻找帧头并累积至 64 字节，核对类型、CRC、seq、固件主版本 4 与参数格式 4；匹配请求后再判断错误码和故障。串口一次 `read` 不保证取得整帧。CRC 不符时滑动查找下一个帧头；丢弃不匹配的旧序号帧，不把它当作本次成功应答。参数应答还应核对参数 ID 和作用域。

多字节值必须手动按小端组合，再按字段恢复符号。不要直接把接收缓冲区强转为结构体；注意编译器填充、对齐及有符号整数解释。

## 8. 心跳、故障恢复和推荐时序

1. 上电后初始化串口，先 PING，再发 `0x14`；确认 V4.3、参数格式和状态。
2. 发 `0x13` 停止，确认全部模式和 PWM 为 0；如有故障，排查原因后发 `0x19`，再查询确认故障清除。计数清零时还应保证机械静止。
3. 在全部停止时，通过 `0x20/0x21` 核对和配置参数，随后读回确认。
4. 先发单台低 PWM 验证方向和反馈，再使用速度闭环或四台混合控制。
5. 运行期间由一个 UART 任务统一发送请求，每次等待匹配应答，再发送下一条；建议心跳 `0x18` 每 100 ms 调度一次，可按需要另发状态查询。
6. 正常结束发 `0x13` 或减速停止，减速期间继续心跳，直到反馈确认全部停止；发生通信异常时取消待发旧运动目标，不自动恢复运动。

100 ms 是 ESP32 端调度建议，不是固件新增的固定规则。默认失联超时为 1000 ms，可通过全局参数 128 设置为 200～10000 ms；心跳周期和应答等待时间应为实际超时值留足余量。应答超时后进入通信故障处理，先尝试停止，不继续把旧运动目标排队重发；不能把“没收到应答”判断为命令未执行。

**只有成功的运动命令和成功的心跳续期失联计时。** PING、查询、参数访问和无效指令均不续期；心跳续期当前已接受的全部目标，不会清故障。故障后按“停止 → 排查原因 → 清故障 → 确认状态 → 操作者重新给定目标”恢复。

| 故障位 | 含义 |
|---|---|
| `0x01` | 有效运动命令/心跳超时 |
| `0x02` | 接收溢出或 UART 接收错误 |
| `0x04` | 堵转、无反馈或输入捕获过捕获 |
| `0x08` | 控制调度超时 |

故障位可叠加。任一故障会关断四路 PWM；软件停止不等于独立硬件急停。文本和二进制请求也应统一串行发送；STM32 对超过 100 ms 无新数据的未完成帧会重新同步，避免把一帧拆成间隔过大的多次发送。
